# Contributing to Nuzky

Thanks for helping. Nuzky is a prototype, so the code moves fast; open an issue before a large change, so we can agree on the direction first.

The rules for code changes are in [AGENTS.md](AGENTS.md), for people and coding agents alike. The two that surprise people most: everything on GitHub is in English, and a fix is not done until an end-to-end test would have caught the bug.

## Set up a checkout

1. Install the build dependencies for your system from [docs/BUILDING.md](docs/BUILDING.md) (Rust 1.94+, Node 22.12+, FFmpeg, clang, cmake, WebKitGTK on Linux).
2. Turn on the repository's git hooks. The pre-push hook scans for secrets and blocks video and audio files:

   ```sh
   git config core.hooksPath .githooks
   ```

   It needs [gitleaks 8.30.1](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1).
3. Run the app with its own data folders, the way the end-to-end tests do. Then it never opens or autosaves your own projects and never attaches to a Nuzky you have open. Use a terminal just for this:

   ```sh
   npm install
   export XDG_DATA_HOME=$PWD/tmp-test/dev/data XDG_CACHE_HOME=$PWD/tmp-test/dev/cache XDG_RUNTIME_DIR=$(mktemp -d)
   npm run tauri dev
   ```

   This works on Linux. macOS and Windows ignore these variables and keep Nuzky's data in `~/Library` and `AppData`, so there develop under a user account that does not hold your own Nuzky projects.

The first build compiles FFmpeg bindings, wgpu and whisper.cpp; compiling the tests in a clean checkout takes about 7 minutes.

The full local gate also needs the tools for the UI flows and the dependency audits. On Fedora or Nobara:

```sh
sudo dnf install gamescope webkitgtk6.0 espeak-ng python3-pillow python3-xlib qemu-user-static-x86
cargo install --locked cargo-deny@0.20.2
```

On macOS the gate runs everything but the check without AVX2, which needs x86-64 Linux. Besides the build dependencies from [docs/BUILDING.md](docs/BUILDING.md) it needs:

```sh
brew install flock espeak-ng ffmpeg-full
cargo install --locked cargo-deny@0.20.2
python3 -m pip install --user Pillow numpy
```

## Check your change

| What | Command |
| --- | --- |
| Frontend lint and build | `npm run lint` and `npm run build` |
| Rust tests by name | `cargo test --workspace <name>` (`-p <crate>` builds most dependencies again with other features) |
| Tests that need media and models | `scripts/fixtures.sh`, then `XDG_DATA_HOME=$PWD/tmp-test/xdg/data cargo test --workspace <name> -- --ignored` |
| A UI flow in the real app | `python3 scripts/repro.py <flow>` (`--list` shows them) |
| Everything, before a merge | `scripts/check.sh` (tens of minutes) |

`scripts/repro.py` runs the app with its own data folders, so it never touches your projects, and out of your way: in a headless gamescope on Linux, off screen and never in front on macOS. Run the CLI and `nuzky mcp` by hand from the terminal where you exported the variables above, so they use the same folders and find that app.

Test media are generated by `scripts/fixtures.sh` from FFmpeg test patterns and synthetic speech. Never commit a real video or recording, not even a short one.

`src/lib/types.ts` is generated from the Rust types. After changing a type the UI sends or receives, write it again:

```sh
NUZKY_WRITE_TYPES=1 cargo test -p nuzky-app typescript_types
```

## Send a pull request

- Branch from a fresh `main`, keep one change per pull request, and rebase before opening it.
- Fill in the template: the problem, the solution and how you verified it. A change you can see needs a screenshot from `tmp-test/repro/<flow>/`; motion needs a short video.
- GitHub runs lint, both builds and the Rust tests on every pull request that is not a draft (`.github/workflows/checks.yml`). While the repository is private, it runs them only on pull requests with the `ci` label. The maintainer runs `scripts/check.sh` with the UI flows before merging.
- A change of behaviour or keys goes into [docs/INTERACTION.md](docs/INTERACTION.md) in the same pull request, a visual change into [DESIGN.md](DESIGN.md).

By contributing you agree that your contribution is licensed under GPL-3.0-or-later, like the rest of Nuzky.

## Security

Report vulnerabilities privately, as [SECURITY.md](SECURITY.md) describes, not in a public issue.
