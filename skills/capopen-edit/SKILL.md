# Edit with CapOpen

Use MCP tools for every project change. Never write the project JSON directly. Media, transcription and export stay local; tool transcripts and frame images are visible to your model.

1. `get_state`: identify main-track assets, source ranges, canvas, revision and any open run. Read the whole transcript before deciding what belongs in the edit.
2. `transcribe` each talking asset (language `cs` for Czech, prefer an installed multilingual model). Poll `job` with pauses until done; the job id is also `transcript_id`. Keep source word timestamps for precise edits.
3. `analyze` silences and fillers. Poll those jobs too. Silence detection proposes breath-padded quiet ranges, not editorial decisions. Fillers require the asset transcript id. Read words around every proposal; do not cut an intentional word just because it appears in a filler dictionary.
4. Plan source ranges to KEEP across the whole recording, including its conclusion. For an unspecified talking-head reel, aim around 90 seconds (roughly 80–100), unless the goal needs another duration. Reach the target by removing retakes, false starts, detours and repeated points, not whole topics. When a sentence restarts or is retaken, keep the LAST complete take and cut earlier attempts. For repeated closing calls to action ("napiš mi do komentáře…"), keep at most one clean take, or none if none is clean. Cut tight: about 0.08 s before the first word and 0.12 s after the last word of a kept passage; shorten internal pauses to about 0.3 s. Calculate retained duration before editing. Preserve negations, meaning and whole words; Whisper boundaries are estimates, so inspect cut-adjacent words.
5. `begin_run`, then `apply_edits` with `rippleDeleteRanges`. Supply a fresh request id for each new batch; retry the same content with the same id. All times are integer microseconds (1 second = 1000000), ranges `[start,end)`. Map source time to timeline: `startUs + (sourceTime - sourceInUs) / speed`, limited to each retained clip. Put all deletion ranges for one timeline snapshot in ONE command. It cuts every track and closes gaps; `keepTrackIds: []` keeps layers synchronized. Main-track clips always repack from zero. Read returned ids/times before more edits.
6. `build_captions` from the asset transcript after cuts; it maps words through the retained source ranges. Reels: at most 3 words and 15 characters, including spaces and punctuation. Prefer `max_words: 2`, `max_chars: 15` for brisk spoken captions; allow 3 when the cadence needs it. It creates or replaces ONE `Captions` track, preserving other text. A longer single word stays intact. Omit `style` to use the app’s Reel preset (size 95, white, regular weight, black stroke 7.5, no background). Prefer this default unless the user requests another look. Inspect and adjust; don't stack duplicate caption tracks. For multiple speaking assets, transcribe the final timeline for captions: each build replaces the entire Captions track.
7. For talking-head reels, use a constant base zoom around 1.1 on every main clip, plus a few punch-ins to 1.3–1.4 on emphasis with `updateClip`. First split at phrase boundaries if needed. A transform is a complete object: `{"x":0,"y":0,"scale":1.2,"rotation":0,"opacity":1}`. Vary emphasis deliberately; keep the face in frame.
8. `inspect_frames` around cuts, caption changes and zooms; check spelling, readable size, framing and missing content. Fix transcription errors without inventing speech. After EVERY manual caption correction, use `get_state` and check `caption_stats.max_chars <= 15` and `max_words <= 3`. If a corrected multiword caption is too long, use `splitClip` at its actual word boundary and `updateClip` the two texts; never abbreviate the speaker's words just to fit. A single long word is the documented exception. Check duration and that the ending still contains the conclusion. Fix problems within the same run. `end_run(keep)` makes the whole run one Undo; discard restores the checkpoint. A run auto-keeps after 2 minutes without calls, so plan before opening it.
9. `export_video` to a new path (portrait reel: short side 1080, 30 fps, recommended quality). Poll until done. Report the actual output path and duration, and any uncertainty in speech recognition.

Jobs render/read immutable snapshots and return their revision and session_epoch. An asset transcript can survive timeline edits; a timeline transcript must be regenerated after audio changes. `undo_run` works only for the last kept run in the current session. If `get_state` reports `recovery_checkpoint`, ask the user whether to keep current edits or restore the checkpoint. Only after their choice, call `resolve_recovery(action: "keep"|"restore")` before opening a run. Both choices remove the checkpoint; restore validates and saves its project.
